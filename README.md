## Этап 3.0

Проверяем работу стандартных команд cmd.exe с альтернативными потоками. Создаем текстовый поток с помощью команды `echo`:
 ```
echo "Секретные данные" > test.txt:secret.txt
```

Пробуем прочитать поток командой `type` через оператор перенаправления ввода:
```
type < test.txt:secret.txt
```
Результат:
```
Ошибка в синтаксисе команды.
```

Причина в том, что команда  `type` в `cmd.exe` изначально не поддерживает синтаксис альтернативных потоков данных (ADS) вида `файл:поток`

Пробуем прочитать поток командой `more` через оператор перенаправления ввода:
```
more < test.txt:secret.txt
```

Результат:
```
"Секретные данные"
```

Проверяем, отображает ли команда `dir` наличие скрытого потока:
```
dir test.txt
```

Результат:
```
26.10.2026 16:47 0 test.txt
```


Проверяем работу оператора дозаписи `>>` с помощью `echo` и читаем результат через `more`:
```
echo "Вторая строка" >> test.txt:secret.txt
more < test.txt:secret.txt
```

Результат:
```
"Секретные данные"
"Вторая строка"
```


**Вывод:** Стандартная команда `echo` поддерживает запись и дозапись в альтернативные потоки с помощью операторов `>` и `>>`. Команда `type` не поддерживает работу с ADS ни напрямую, ни через `<`. Команда `more` корректно извлекает данные из потока при использовании перенаправления ввода (`more < файл:поток`). Команда `dir` не отображает наличие альтернативных потоков, показывая только нулевой размер основного файла.

## Этап 4.0

Проверяем работу графических программ с альтернативными потоками данных. Открываем папку с файлом `test.txt` в Проводнике Windows.
*Результат:* Проводник отображает файл `test.txt` размером **0 КБ**. Скрытые потоки в графическом интерфейсе не видны.

Для записи читаемого русского текста в поток использовалась команда PowerShell с параметром `-Stream` (так как синтаксис `файл:поток` в PowerShell не работает, он воспринимает двоеточие как имя диска):
```
powershell -Command "Set-Content -Path test.txt -Stream secret.txt -Value 'Секретные данные из потока' -Encoding Unicode"
```

Запускаем Блокнот (Notepad) из командной строки, передавая ему в качестве аргумента имя скрытого потока:
notepad test.txt:secret.txt


Результат:
Секретные данные из потока


**Вывод:** Проводник Windows полностью игнорирует альтернативные потоки и показывает только основной файл нулевого размера. Однако Блокнот способен корректно открыть и отобразить содержимое потока, если запустить его с синтаксисом `файл:поток`. При этом кодировка имеет значение: для корректного отображения русского текста в Блокноте поток был записан в кодировке Unicode с помощью `Set-Content` с параметром `-Stream`. Это подтверждает, что ADS являются полноценным хранилищем данных, доступным не только для командной строки, но и для некоторых GUI-приложений.


### Дополнительный пункт 1. Хранение и извлечение бинарных файлов

Для демонстрации скрытого хранения исполняемых файлов в альтернативных потоках был использован системный калькулятор Windows (`C:\Windows\System32\calc.exe`). 

Создаем файл-приманку `readme.txt` и перенаправляем в его скрытый поток бинарный файл:
```
type nul > readme.txt
type C:\Windows\System32\calc.exe > readme.txt:calc.exe
```

Проверяем размер файла-приманки:
```
dir readme.txt
```

Результат:
```
26.10.2026 17:02 0 readme.txt
```

Файл снаружи кажется абсолютно пустым (0 байт).

Извлекаем скрытый бинарный файл обратно с помощью PowerShell (для корректной работы с бинарными данными):
```
powershell -Command "Get-Content -Path readme.txt -Stream calc.exe -Encoding Byte -ReadCount 0 | Set-Content -Path extracted_calc.exe -Encoding Byte"
```

Проверяем размер извлеченного файла:
```
dir extracted_calc.exe
```

Результат:
```
26.10.2026 17:02 49 152 extracted_calc.exe
```

Файл извлечен без потерь (размер 49 152 байта) и успешно запускается командой `start extracted_calc.exe`.

**Вывод:** Альтернативные потоки NTFS позволяют скрыто хранить и извлекать бинарные (исполняемые) файлы любого размера. Сторонние программы и Проводник Windows не видят наличия посторонних данных внутри пустого текстового файла. Это создает серьезную угрозу информационной безопасности, так как вредоносное ПО (вирусы, трояны, скрипты) может быть скрыто в безобидных файлах (картинках, текстах) и незаметно для антивирусов, которые проверяют только основной поток, запущено на системе.
