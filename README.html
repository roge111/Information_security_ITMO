Этап 4.0

Проверяем работу графических программ с альтернативными потоками данных. Открываем папку с файлом test.txt в Проводнике Windows. Результат: Проводник отображает файл test.txt размером 0 КБ. Скрытые потоки в графическом интерфейсе не видны.

Для записи читаемого русского текста в поток использовалась команда PowerShell с параметром -Stream (так как синтаксис файл:поток в PowerShell не работает, он воспринимает двоеточие как имя диска):

powershell -Command "Set-Content -Path test.txt -Stream secret.txt -Value 'Секретные данные из потока' -Encoding Unicode"

Запускаем Блокнот (Notepad) из командной строки, передавая ему в качестве аргумента имя скрытого потока: notepad test.txt:secret.txt

Результат: Секретные данные из потока

Вывод: Проводник Windows полностью игнорирует альтернативные потоки и показывает только основной файл нулевого размера. Однако Блокнот способен корректно открыть и отобразить содержимое потока, если запустить его с синтаксисом файл:поток. При этом кодировка имеет значение: для корректного отображения русского текста в Блокноте поток был записан в кодировке Unicode с помощью Set-Content с параметром -Stream. Это подтверждает, что ADS являются полноценным хранилищем данных, доступным не только для командной строки, но и для некоторых GUI-приложений.

Дополнительный пункт 3. Разграничение доступа к файлу и потоку

Для выяснения того, совпадают ли разграничения доступа к файлу с разграничениями доступа к потоку, был проанализирован механизм работы списков управления доступом (ACL) в файловой системе NTFS.

Суть механизма: В Windows права доступа (ACL) назначаются на дескриптор безопасности самого файла, а не на отдельные его атрибуты или потоки. В системе безопасности Windows не существует отдельных разрешений вида «Чтение потока» или «Запись потока». Все права (на чтение, запись, изменение, удаление) применяются к файлу как к единому объекту.

Практический вывод: Разграничения доступа к файлу и к его скрытым потокам полностью совпадают. Если пользователь имеет право на чтение файла test.txt, он автоматически получает право на чтение всех его альтернативных потоков (например, test.txt:secret.txt или test.txt:aaa.txt).

Невозможно настроить политику безопасности так, чтобы, например, основной поток файла был доступен для чтения всем пользователям, а скрытый поток — только администратору. Из-за этого механизм ADS нельзя использовать как средство дополнительного разграничения доступа (например, для сокрытия конфиденциальных данных от коллег, у которых есть доступ к общей папке).

Однако с точки зрения уязвимости, это означает обратное: антивирусы и средства защиты, работающие под учетной записью пользователя, имеют техническую возможность прочитать скрытые потоки (если умеют), но вредоносный код может маскироваться, рассчитывая на то, что легитимные программы проверяют только основной поток. Файл извлечен без потерь (размер 49 152 байта) и успешно запускается командой start extracted_calc.exe.

Вывод: Альтернативные потоки NTFS позволяют скрыто хранить и извлекать бинарные (исполняемые) файлы любого размера. Сторонние программы и Проводник Windows не видят наличия посторонних данных внутри пустого текстового файла. Это создает серьезную угрозу информационной безопасности, так как вредоносное ПО (вирусы, трояны, скрипты) может быть скрыто в безобидных файлах (картинках, текстах) и незаметно для антивирусов, которые проверяют только основной поток, запущено на системе.

Общий вывод по лабораторной работе

В ходе выполнения лабораторной работы были изучены механизмы работы альтернативных потоков данных (Alternate Data Streams, ADS) в файловой системе NTFS.

Основные результаты: 1. Экспериментально подтверждено, что при создании и записи данных в скрытый поток, размер самого файла (основного потока) не изменяется и отображается как 0 байт. Однако данные в потоке реально существуют и занимают дисковое пространство. 2. Исследование зависимости свободного места показало, что альтернативные потоки занимают место на диске строго пропорционально объёму записанных в них данных (коэффициент 1:1), при этом накладные расходы файловой системы минимальны. 3. Доказано, что содержимое потоков можно не только прочитать на экране (с помощью more), но и корректно извлечь обратно в обычный файл без потери данных. 4. Выявлено, что стандартные команды cmd.exe (например, echo, type, dir) и графические программы (Проводник Windows) не отображают наличие потоков. При этом некоторые программы (Блокнот) способны открыть поток, если передать ему путь в формате файл:поток. 5. Дополнительно продемонстрирована возможность скрытого хранения и успешного запуска бинарных исполняемых файлов (на примере calc.exe), спрятанных внутри безобидного пустого текстового файла.

Значение для информационной безопасности: Механизм ADS представляет собой серьезную угрозу безопасности. Злоумышленники могут использовать потоки для сокрытия вредоносного кода (вирусов, троянов, скриптов), конфиденциальных данных или логов от системных администраторов. Проводник и базовые сканеры не видят эти данные. Кроме того, было выяснено, что разграничения прав доступа не позволяют защитить поток отдельно от файла (права наследуются), что исключает использование ADS для легитимного разделения прав, но позволяет обходить некоторые механизмы защиты. Для противодействия данной угрозе необходимо использовать специализированный инструментарий (например, утилиту streams.exe от Sysinternals) для поиска и очистки скрытых потоков на дисках.
